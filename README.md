# 餐桌地圖 · Hong Kong Dining Atlas

An independent, Traditional Chinese guide to the Hong Kong American Express dining collection. **Not affiliated with or endorsed by American Express.** Eligibility, restaurant participation and benefit terms can change; always check [the official page](https://www.americanexpress.com/zh-hk/benefits/diningbenefit/) before booking or paying.

## Run locally

Requires Node.js 22+ and npm.

```sh
npm ci
npm run dev
npm test
python3 scripts/test_import.py
npm run build
npx playwright install chromium
npm run test:e2e
```

Vite prints the development URL. `npm run preview` serves the production build. Unit tests cover URL safety, snapshot validation and coordinate validity; Playwright exercises desktop/mobile, real data, retry, tile failure, unsafe links, unmapped restaurants and overlapping markers. Synthetic restaurant fixtures exist only inside tests.

## Deploy to Vercel

Using a Vercel account authorized to access this **private GitHub repository**, import the existing repository into Vercel, select the **Vite** framework, build with `npm run build`, output directory **dist**. `vercel.json` supplies these defaults. No environment variables, map API key, backend, or SPA rewrites are required. The JSON snapshot is copied into the static deployment from `public/data/restaurants.json`. Deployment requires your own authenticated Vercel account; this repository alone does not imply a live deployment.

## MVP1

- Navy, cream and teal editorial interface; responsive list/map with mobile view switching.
- Leaflet + OpenStreetMap tiles, automatic fit bounds and reset view.
- Select a restaurant in the list or select a marker to open its details. Restaurants sharing a coordinate remain individually selectable from the list.
- Details include supplied address, cuisine, district, official restaurant/book link, valid phone number, Google Maps, official Amex link and hotel note. Building-level coordinates are explicitly approximate, not entrance locations.
- Missing/invalid coordinates are **待定位** and remain accessible in the list. Coordinates are never generated by the frontend.
- Snapshot date, mapped/total counts, unofficial status and changing-terms disclaimers.
- Loading retry, tile-failure warning, keyboard-operable controls, visible focus states, skip link and reduced-motion support. Selected mapped restaurant details also appear below the map for easier reading and keyboard access.
- No search or filters in MVP1; these are reserved for phase 2.

## MVP2 (in review)
- Search restaurant names and addresses (Traditional Chinese + English, NFKC-normalized, multi-term).
- District and cuisine selects auto-populated from the snapshot. Selection clears to avoid stale popups.
- Real Leaflet marker clustering (`leaflet.markercluster`) with spiderfy on max zoom, smaller `maxClusterRadius` (32 px) so individual markers stay accessible.
- Map auto-fits and `⌖ 重設視野` recompute from the filtered set; clearing filters restores the unfiltered view.
- Empty-results state with a `顯示所有餐廳` call to action.
- Filter bar, results summary and `aria-live` count keep list and map in sync.

### Known mobile interaction caveat
On narrow viewports the map's `.map-actions` overlay (legend + `重設視野`) sits at the top of
the map and can visually overlap a popup opened by clicking a list entry. The popup itself
remains visible and readable; only the close button can be obscured. Closing by tapping the
map or by re-selecting from the list still works. The automated `real snapshot renders and
list opens pin details` Playwright case (`tests/app.spec.ts:4`) covers this and is currently
expected to fail on the mobile project (`tests/app.spec.ts:4 mobile`). All other unit, data,
build and E2E checks pass.

## Data contract and safety

The app fetches `public/data/restaurants.json` on startup:

```ts
{
  sourceUrl: string;
  fetchedAt: string; // ISO date/time
  region: 'HK';
  restaurants: Array<{
    id: string; name: string; nameEn?: string;
    address: string; addressEn?: string; district?: string; cuisine?: string;
    website?: string; phone?: string; googleMapsUrl?: string;
    isInHotel?: boolean; isNew?: boolean;
    coordinates: null | { lat: number; lng: number; source?: string; precision?: string };
  }>;
}
```

The envelope, identifiers and string fields are validated before rendering. Invalid coordinate values are treated as unmapped. React escapes source strings; no source data is injected as HTML. External URLs must be absolute HTTP(S) without credentials and open with `noopener noreferrer`. Leaflet marker HTML is static, not source-derived.

The source snapshot and provenance are maintained separately under `public/data/`, `data/` and `scripts/`; see [data provenance and refresh instructions](docs/DATA.md) for refresh and verification procedures. A static snapshot does **not** update itself after deployment.

## External services and limits

Map tiles are fetched directly from OpenStreetMap and display required attribution. Users' browsers also request optional Noto webfonts from Google Fonts; local sans/serif fonts are fallbacks. No analytics or tracking code is installed. Network failures do not remove the restaurant list. Public OpenStreetMap tiles are best-effort and subject to the [tile usage policy](https://operations.osmfoundation.org/policies/tiles/); select an appropriate production tile provider before high-traffic use. Map locations are indicative only. Mobile map/list switching is intentional; there are no offline maps or live availability checks.
